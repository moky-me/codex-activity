# Разработка и выпуск

## Инструменты и тесты

Для сборки нужны macOS, Swift 6 из Xcode или Command Line Tools, Python 3 и системные утилиты macOS. У проекта нет внешних Swift-пакетов. Минимальная цель сборки — macOS 14.

```sh
swift run ActivityCoreTests
./scripts/test-panel.sh
./scripts/build.sh
```

Тесты ядра используют синтетические базы и локальный тестовый IPC. Тесты панели проверяют разметку, состояния, анимации и настройки на тестовых данных. Они не требуют входа в Codex. Для проверки поведения в настоящем окне есть [сценарий нового Mac](setup.md#проверка-на-новом-mac).

- `Sources/ActivityCore` читает локальные данные, определяет статусы и готовит карточки.
- `Sources/ActivityPanel` содержит окно в `AppDelegate.swift`, шапку и меню в `PanelViews.swift`, прокрутку и переходы в `NativeCardScroll.swift`, карточку и токены в `CardView.swift` и `CardTokenRow.swift`. Общие цвета и эффекты наведения находятся в `PanelStyle.swift`.
- `Sources/ActivityLauncher` содержит системный помощник автозапуска.
- `Sources/ActivityDiagnostics` содержит локальную диагностику. Режимы `--titles` и `--audit` выводят данные чатов. Не прикладывайте этот вывод в публичные задачи.

## Универсальный пакет и выпуск

```sh
./scripts/package.sh
```

Команда собирает приложение и помощник для arm64 и x86_64, подписывает их, создаёт ZIP и после распаковки проверяет подпись, обе архитектуры и точный состав приложения. ZIP и `SHA256SUMS.txt` находятся в `build/release`. Проверочная распаковка выполняется в системном временном каталоге, где File Provider не добавляет к приложению FinderInfo.

Обновляйте версию и номер сборки в `version.json`. Для GitHub Release берите артефакт `codex-activity-macos` из успешного запуска **macOS tests and package** для точного коммита в `main`. Скачайте артефакт, сверьте сумму через `shasum -a 256 -c SHA256SUMS.txt`, привяжите тег `v<версия>` к этому коммиту и приложите ZIP и файл с суммой к выпуску.

## Связь с основной разработкой

У публичной версии своя история Git, идентификаторы приложения и помощника, версии и процесс выпуска. Синхронизация выборочная. Из другой ветки разработки переносите проверенный патч для конкретной функции и её тестов. Просматривайте публичный diff перед коммитом. Для обратного переноса используйте тот же принцип. Храните соответствие ревизий в журнале сопровождающей команды.

Переносимые части — ядро, интерфейс и тесты. Публичные идентификаторы, настройки выпуска и руководство остаются в этой ветке. Пользовательские данные, конфигурации, внутренние ссылки и историю других репозиториев не переносите.
